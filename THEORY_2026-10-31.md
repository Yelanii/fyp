# Core 3: when does checking cost more than it saves? (31 October 2026)

Code: `ereplan/theory.py` (exact formulas), `ereplan/theory_check.py` (check against the simulator, figure),
`tests/test_theory.py` (8 tests). Result folder: `results/theory_check_20261031-194108/`.

## 1. The idea in simple words

A checker (an LLM judge) sometimes says "wrong" about a correct answer. This is a **false alarm**.
The usual fix is to retry the step and check again. That fix assumes the second verdict is a new, independent
coin flip. A deterministic judge (temperature 0) reads the same kind of input and gives the **same** verdict
again. Our real checkers repeated their false alarms 99–100% of the time at temperature 0 (parts D and E3).

This document proves three things about that situation:
1. **Retrying cannot fix it.** With a judge that always repeats itself, a falsely flagged step can only end in one
   of two ways: it fails, or the agent accepts a *wrong* answer. It can never end with a correct answer accepted.
2. **The risk is badly underestimated.** A rule that assumes independent verdicts thinks a correct step fails with
   probability f^(R+1). The true probability is f. With f = 0.15 and 2 retries, that is **44 times** higher.
3. **The rule then checks when it should not.** There is always a range of tool success rates where such a rule
   decides to check, yet never checking would be cheaper. This range gets wider as the judge repeats itself more.
   A cross-check on a second tool (rule v5) is almost unaffected, because it does not ask the same judge again.

Everything is checked against the project's own simulator. The worst gap between the formulas and simulated
results is 0.46%, which is within Monte Carlo noise.

## 2. The model (one step of a task)

Each attempt costs w (tool price), plus c if it is checked. An attempt is:

| Outcome | Probability |
|---|---|
| correct | p |
| loud failure (the agent sees it, free) | l = (1 − p) ρ |
| silent failure (looks correct) | s = (1 − p)(1 − ρ) |

- A check catches a silent failure with probability q.
- A check flags a correct attempt when the judge's **verdict state** I_b equals 1.
- The verdict state follows the simulator's two-state chain:
  - I_0 ~ Bernoulli(f);
  - for each later attempt, I_b = I_(b−1) with probability π (the judge repeats itself), otherwise a fresh
    Bernoulli(f) draw.
  - π = 0 means independent verdicts; π = 1 means a fully repeatable judge.
- The agent retries after a loud failure or a flag, at most R times. If every attempt ends in a detected failure,
  the step fails at cost F. An accepted silent failure costs L.

Policies on the step:

| Policy | What it does |
|---|---|
| **N** | Never check. |
| **C** | Check every attempt; retry on a flag. This is how always-check and rules v2–v4 handle a flag. |
| **X** | Check every attempt. On a flag, run the step on an alternative tool (success rate a) and compare. If they agree, keep the output. If they disagree, use the alternative's output. If the alternative fails loudly, retry. Two wrong outputs never agree. This is rule v5. |

Two facts about the verdict chain are used below. Write μ = (1 − f, f) for its stationary distribution.
- The transition matrix is P = π·Id + (1 − π)·1μᵀ, so P^d = π^d·Id + (1 − π^d)·1μᵀ.
- Hence P(I_(b+d) = 1 | I_b = 1) = f + (1 − f) π^d.

## 3. Results

**Theorem 1 (exact loss).** Let κ(i) be the chance that an attempt in verdict state i leads to a retry, and A(i)
its expected immediate cost. Let M_k = E[κ(I_0) κ(I_1) ⋯ κ(I_(k−1))] (M_0 = 1). For any policy whose per-attempt
retry chance and cost depend only on I_b:

  V = Σ_(k=0..R) E[A(I_k) Π_(b<k) κ(I_b)] + F · M_(R+1).

For the three policies:

| Policy | κ(I) | A(I) |
|---|---|---|
| N | l | w + sL |
| C | l + sq + p·I | w + c + s(1 − q)L |
| X | l + (p·I + sq)(1 − a)ρ | w + c + s(1 − q)L + (p·I + sq)(w_B + (1 − a)(1 − ρ)L) |

The code computes V by a forward pass over (attempt, verdict state). The two extreme cases have closed forms.
Write κ_0 = l + sq + pf, κ_b = l + sq + p and κ_g = l + sq, and let G(κ) = A·(1 + κ + … + κ^R) + F κ^(R+1).
- At π = 0: V_C = G(κ_0).
- At π = 1: V_C = f·G(κ_b) + (1 − f)·G(κ_g).

*Proof.* The step reaches attempt k exactly when every earlier attempt led to a retry. Given the verdict states,
the attempt outcomes are independent of each other and of the chain. Taking expectations gives the sum. At π = 0
the I_b are independent, so M_k = κ_0^k. At π = 1, I_b = I_0 for every b. ∎

**Proposition 1 (a retry cannot fix a repeated false alarm).** Let π = 1, and suppose a correct attempt on the
step is flagged. Then the step ends in one of two ways: it fails (cost F), or it accepts a silently wrong output
(cost L). It never ends with a correct output accepted.

*Proof.* With π = 1, the first false alarm shows I_b = 1 for every attempt. So every later correct attempt is
flagged too. An attempt is accepted only if it is not flagged, and with I = 1 that happens only for a silent
failure the check misses. ∎ (Tested directly on the simulator's outcomes: `test_retry_cannot_rescue_...`.)

**Theorem 2 (persistence always makes checking-with-retries more expensive).** V_C is non-decreasing in π. It is
strictly increasing when p > 0, 0 < f < 1, and either R ≥ 2, or R = 1 and F > 0. When R = 0, V_C does not depend
on π.

*Proof.* For policy C, A does not depend on I, and κ(I) = κ_g + p·I. Expand the product over subsets S of the
attempts {0, …, k−1}:

  M_k = Σ_S κ_g^(k−|S|) p^|S| P(I_b = 1 for all b in S).

For S = {b_1 < … < b_m}, the Markov property and the P^d formula give

  P(I_b = 1 for all b in S) = f · Π_j [f + (1 − f) π^(b_(j+1) − b_j)].

Each factor is non-decreasing in π, so every M_k is too. Since V_C = A(M_0 + … + M_R) + F·M_(R+1) with A, F ≥ 0,
V_C is non-decreasing.

For strictness we need a subset with |S| ≥ 2 and positive weight. This happens when k ≥ 2. The first such term is
M_2, which carries weight A > 0 when R ≥ 2, or weight F when R = 1. When R = 0 only M_0 and M_1 appear, and
M_1 = κ_g + pf does not depend on π. ∎

**Corollary 1 (the failure risk a retry rule underestimates).** For a correct step (p = 1), the chance that all
R + 1 attempts are flagged is f (f + (1 − f) π)^R. A rule that assumes independent verdicts uses f^(R+1). The
ratio is ((f + (1 − f)π)/f)^R, which equals f^(−R) at π = 1.

| f | R | Assumed (π = 0) | π = 0.8 | π = 1 | Ratio at π = 1 |
|---|---|---|---|---|---|
| 0.05 | 2 | 0.00013 | 0.033 | 0.050 | 400× |
| 0.14 | 2 | 0.0027 | 0.096 | 0.140 | 51× |
| 0.15 | 2 | 0.0034 | 0.103 | 0.150 | 44× |

The value f = 0.14 is our real qwen2.5:1.5b checker.

**Corollary 2 (rule v4's false-alarm cost is the exact p → 1 case).** At p = 1:

  V_C − (w + c) = f [g^R F + (1 + g + … + g^(R−1))(w + c)],   where g = π + (1 − π) f.

This is exactly the false-alarm cost of Rule_v4_pi. At π = 1 it is rule v4's FA term. So the cost model the rule
already uses is a special case of Theorem 1 (`test_p_equal_one_gives_rule_v4_false_alarm_cost`).

**Theorem 3 (a rule that ignores persistence checks when it should not).** Let D_π(p) = V_C(π, p) − V_N(p), the
extra loss of checking. A rule that assumes π = 0 checks on S_0 = {p : D_0(p) ≤ 0}. Its **wrong-check region** is

  W_π = {p in S_0 : D_π(p) > 0},

the success rates at which it checks although never checking is strictly cheaper. Under the strictness conditions
of Theorem 2:
- (a) W_π ⊆ W_π′ whenever π ≤ π′: the region only grows as the judge becomes more repeatable.
- (b) If S_0 has a boundary point p* in (0, 1), meaning the rule checks at some success rates but not all, then
  p* is in W_π for every π > 0. Because D_π is continuous in p, W_π also contains every p in S_0 close enough to
  p*. So W_π is non-empty.
- (c) On W_π, the extra loss of checking is at most V_C(π, p) − V_C(0, p).

*Proof.* (a) follows from Theorem 2, because V_N does not depend on π. (b) At a boundary point,
D_0(p*) = 0 < D_π(p*) by Theorem 2 (strict), and D_π is a polynomial in p. (c) On S_0,
D_π = D_0 + (V_C(π) − V_C(0)) and D_0 ≤ 0. ∎

Numbers (exact formulas, R = 2, q = 0.8, ρ = 0.5, w = 20, c = 3.7):

| f | L = F | π | Wrong-check region (p) | Max extra loss per step |
|---|---|---|---|---|
| 0.15 | 360 | 0.5 | 0.729–0.911 | 17.8 |
| 0.15 | 360 | 0.8 | 0.585–0.911 | 36.3 |
| 0.15 | 360 | 1.0 | 0.492–0.911 | 51.9 |
| 0.05 | 360 | 1.0 | 0.826–0.960 | 18.6 |
| 0.15 | 120 | any | empty (the rule never checks here, so it cannot check wrongly) | — |

**Proposition 2 (why the cross-check barely depends on persistence).** For policy X, π enters V only through joint
moments E[I_(b_1) ⋯ I_(b_m)] with m ≥ 2. Each such term is multiplied by at least one factor
δ_X = p(1 − a)ρ, the chance that a flag goes to a retry *because the alternative failed loudly*. For policy C the
same factor is δ_C = p. So persistence matters for X roughly (1 − a)ρ times as much: 0.025 when a = 0.95 and
ρ = 0.5.

Measured exactly at p ∈ {0.8, 0.95} and f ∈ {0.05, 0.15}: the extra loss from π = 0 to π = 1 is under 5% of policy
C's (test), for example +0.09 vs +13.8 at p = 0.95, f = 0.15, R = 1.

*Proof.* Write κ_X(I) = κ_X(0) + δ_X·I and A_X(I) = A_X(0) + γ·I. Expand the products as in Theorem 2. Terms with
|S| ≤ 1 involve only E[I_b] = f, which does not depend on π. Every term with |S| ≥ 2 contains at least one κ factor
taken at its I-part, so it carries δ_X. ∎

## 4. Check against the simulator

`python -m ereplan.theory_check` runs 36 settings × 3 policies on the simulator's own random outcomes
(`Environment.call`), with 80,000 steps each:
- p ∈ {0.6, 0.85, 0.95}; f ∈ {0.05, 0.15}; π ∈ {0, 0.5, 1}; R ∈ {1, 2}.
- Worst relative error between formula and simulation: **0.46%** (Monte Carlo noise).
- Run time: 14 s on 2 CPU cores.

## 6. What this adds, and its limits

**What it adds.**
- An exact, checkable account of *why* retry-based verification fails with repeatable judges, and by how much.
- A closed-form correction (Theorem 1, Corollary 2) that the rule already uses.
- A guarantee (Theorem 3) that ignoring persistence makes some checks worse than doing nothing.

Among the papers reviewed so far:
- **VRR-Stop** (Wu, Shen, Yang, Peng and Hu, 2026, arXiv:2607.17641v1). Section 3.2 states that the model "treats
  repeated queries on the same plan as conditionally independent observations given the true state". It names
  correlation between repeated queries as a possible violation, but does not model it. Theorem 3 measures what
  that assumption costs inside a priced check-and-retry loop. (Checked in the HTML version, 31 Oct 2026.)
- **Verify-before-retry wrappers** (Mansoor, Phadke and Rana, 2026, arXiv:2608.02645). They check a postcondition
  before retrying a tool call. The paper notes that strict verifiers can trigger unnecessary retries, but it does
  not measure this, does not price checks, and does not analyse repeated verifier errors. (Abstract-level reading.)
- Kiyani et al. (2026) control errors with a weak and a strong verifier, using two thresholds. Repeated false
  alarms from the same judge are not part of what we have read of it.

Neither paper gives this result as far as we have read, but the search for the exact claim is not yet
systematic. That is the next step in the literature log.

**Limits.**
- One step only. The value of a check for the *switching* decision (DV in the rule) is not part of the theorems.
- The cross-check result assumes two wrong outputs never agree. Shared mistakes are Core 4.
- The mathematics is elementary (Markov chain and an expansion over subsets). The contribution is the result and
  its link to real judges, not new mathematics.
