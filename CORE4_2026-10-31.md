# Core 4: cross-checks when two tools can be wrong in the same way (31 October 2026)

Code: `ereplan/rule_v5s.py` (rule v5 with shared mistakes in its model), `ereplan/core4_exp.py`, the `xc_shared`
setting (σ) in `config.py`, and two guarded branches in `runner.py`.

## 1. The problem in simple words
Rule v5 handles a flag by asking a second tool. If both answers match, it treats the flag as a false alarm. This
assumes that two **wrong** answers never match. That holds for numbers from independent sources. It fails when
both tools copy the same stale source, or when two LLM tools make the same mistake. σ is the chance that two wrong
answers match.

## 2. Two results (no simulation needed)

**Proposition 3 (σ does not change the loss of a fixed cross-check policy).** Take a flagged step whose output is
silently wrong, and an alternative that is also silently wrong:
- if the two outputs match (chance σ), the original is kept, so a wrong answer is accepted;
- if they do not match, the alternative's output is used, which is also wrong.

Both branches leak, at the same cost. In every other case, σ never applies: at least one output is correct, and a
correct output cannot match a wrong one.

So for any policy whose decisions do not depend on what it has observed, the loss distribution does not depend on
σ. σ matters **only through learning**: a matching wrong pair looks like a "false alarm", so a label-free learner
(rule v5):
- overestimates f;
- underestimates q;
- thinks the tool is better than it is.

**Proposition 4 (identifiability).** On checked calls, rule v5 observes five kinds of event:

| Event | Probability |
|---|---|
| loud | (1 − p)ρ |
| none | p(1 − f) + s(1 − q) |
| flag, agree | pfa + sq(1 − a)(1 − ρ)σ |
| flag, disagree | pf(1 − a)(1 − ρ) + sq(a + (1 − a)(1 − ρ)(1 − σ)) |
| flag, alternative loud | (pf + sq)(1 − a)ρ |

Here s = (1 − p)(1 − ρ) and a is the alternative's success rate.
- **One success rate p and one alternative a:** the Jacobian of these probabilities with respect to (q, f, σ) has
  rank 2. So (q, f, σ) cannot be identified without labels: a whole curve of values explains the data equally
  well. The reason is that "none" and "flag, alternative loud" both depend on q and f only through pf + sq.
- **Two different success rates (for example before and after a degradation), or two alternatives with different
  a:** the rank is 3, and the three can be identified. (Checked symbolically with sympy, 31 Oct 2026.)
- **With σ = 0 assumed** (rule v5), the remaining two equations identify q and f exactly. This is why v5 works when
  wrong answers never match.

What this means for the design:
- **Rule_v5_s** adds σ to the checker memory, with a weak prior (mean 0.1).
- Its memory pools every checked call in the run, so the degradation itself supplies the second success rate.
- Before any degradation, the prior on σ is all it has.
- A few labelled calls or a third source would also restore identifiability. These are noted as options; they are
  not built.
